فصل اول: مقدمه و نیازمندی‌ها

۱-۱. بیان مسئله

اداره ثبت اختراعات و علائم تجاری ایالات متحده (USPTO) پورتال عظیمی به نام Open Data Portal دارد که در آن میلیون‌ها سند مربوط به اختراعات ثبت‌شده را به صورت فایل‌های PDF و آرشیوهای فشرده (TAR/ZIP) منتشر می‌کند. این فایل‌ها به تفکیک ماه (از سال ۲۰۰۰ تاکنون) دسته‌بندی شده‌اند.

استخراج دستی این داده‌ها غیرممکن است، زیرا:

  • حجم داده‌ها به چندین ترابایت می‌رسد.
  • سایت USPTO برای دانلود هر فایل از کپچای ریاضی (جمع دو عدد) استفاده می‌کند.
  • برای دسترسی به لینک‌های دانلود، نیاز به احراز هویت دو مرحله‌ای (2FA) است.
  • نشست کاربر (Session) در صورت عدم فعالیت طولانی منقضی می‌شود.
هدف پروژه: طراحی یک سیستم نرم‌افزاری مقاوم، خودمختار و کراس‌پلتفرم که بتواند به صورت ۲۴ ساعته، لاگین کند، کپچاها را با استفاده از بینایی ماشین (OCR) حل کند، فایل‌ها را پیدا کرده و با مدیریت دقیق خطاها آن‌ها را دانلود کند.

نمودار ۲-۱: معماری لایه‌ای سیستم و ارتباط ماژول‌ها

۲-۱. الگوی Supervisor (نظارت و ری‌استارت)

یکی از مهم‌ترین بخش‌های این پروژه فایل runner.ts است. این فایل به عنوان یک پروسه جداگانه اجرا می‌شود و وظیفه آن اجرای فایل اصلی (index.ts) است. سایت USPTO ممکن است به دلایلی مانند به‌روزرسانی، کرش کردن مرورگر Chromium یا محدودیت‌های شبکه، باعث بسته شدن ناگهانی برنامه شود. فایل runner.ts با استفاده از یک الگوریتم Exponential Backoff، در صورت کرش کردن، پروفایل مرورگر را پاک کرده و برنامه را مجدداً راه‌اندازی می‌کند.

نمودار ۳-۱: مدل ارتباطی موجودیت‌ها (ERD)

۳-۱. تحلیل جداول

  • accounts: اطلاعات ورود را نگه می‌دارد. فیلد 2fa_secret بسیار حیاتی است و باید به صورت Base32 (مثل FQDSZUPPTVMVHUMF) ذخیره شود.
  • urls: لینک‌های ماهانه USPTO. فیلد priority تعیین می‌کند کدام لینک زودتر دانلود شود. فیلد status چرخه عمر (draft → scanning → processing → downloaded) را نشان می‌دهد.
  • files: نام هر فایل به همراه حجم مورد انتظار (برای بررسی سلامت فایل پس از دانلود) در اینجا ذخیره می‌شود. وضعیت فایل‌ها شامل registered، downloading، failed و downloaded است.

فصل چهارم: تحلیل ماژول‌های اصلی

۴-۱. ماژول احراز هویت (AuthService)

فرآیند لاگین در سایت USPTO از طریق سیستم Okta انجام می‌شود که شامل سه مرحله است: ورود ایمیل، ورود پسورد و ورود کد 2FA. چالش اصلی، تولید کد 2FA است. تابع generateTotpCode این کار را انجام می‌دهد:

private generateTotpCode(secretOrUri: string | null): string {
    if (!secretOrUri?.trim()) {
        throw new Error("No 2fa_secret registered for this account.");
    }
    const raw = secretOrUri.trim();
    let otp: OTPAuth.TOTP | OTPAuth.HOTP;

    // اگر سکرت به صورت لینک کامل (otpauth://) باشد
    if (raw.startsWith("otpauth://")) {
        const parsed = OTPAuth.URI.parse(raw);
        if (!(parsed instanceof OTPAuth.TOTP)) {
            throw new Error("2fa_secret must be of type TOTP.");
        }
        otp = parsed;
    } else {
        // اگر سکرت به صورت متن خام (Base32) باشد
        const cleaned = raw.replace(/[\s-]/g, "").toUpperCase().replace(/=+$/, "");
        otp = new OTPAuth.TOTP({
            secret: cleaned,
            digits: 6,
            period: 30,
            algorithm: "SHA1",
        });
    }
    return otp.generate(); // تولید کد ۶ رقمی
}

۴-۲. ماژول دانلود و مانیتورینگ (DownloadMonitor)

دانلود فایل‌های چند گیگابایتی نیازمند یک سیستم مانیتورینگ است. اگر اینترنت قطع شود، فایل در پوشه موقت باقی می‌ماند و برنامه فکر می‌کند دانلود در حال انجام است. کلاس DownloadMonitor با روش Polling (هر ۳ ثانیه) حجم فایل در حال دانلود را چک می‌کند.

الگوریتم Stall Detection (تشخیص توقف): اگر حجم فایل در بازه زمانی ۱۰ دقیقه‌ای تغییری نکند (رشد نکند)، خطای DownloadStalledError پرتاب می‌شود تا فایل به عنوان شکست‌خورده علامت‌گذاری شده و از نو تلاش شود.

فصل پنجم: الگوریتم‌های پیچیده

۵-۱. حل کپچای ریاضی با بینایی ماشین (OCR Pipeline)

کپچای سایت USPTO شامل یک عبارت ریاضی است (مثلاً 4+5=). ماژول MathOcrSolver با ترکیب دو کتابخانه Sharp (پردازش تصویر) و Tesseract.js (تشخیص کاراکتر) این مسئله را حل می‌کند:

  1. پیش‌پردازش (Preprocessing): تصویر کپچا گرفته شده و با استفاده از Sharp به خاکستری (Grayscale) تبدیل می‌شود.
  2. تولید واریانت (Variants): برای افزایش دقت، از تصویر ۵ نسخه مختلف با آستانه‌های باینری متفاوت (Thresholds: 128, 160, 190, 210) ساخته می‌شود.
  3. OCR: هر ۵ تصویر به Tesseract داده می‌شود و خروجی متنی آن‌ها گرفته می‌شود.
  4. فیلترینگ Regex: خروجی‌ها با الگوی /^\d\+\d=?$/ بررسی می‌شوند.
  5. رأی‌گیری (Voting): نتیجه‌ای که بیشترین تکرار را در بین ۵ نسخه داشته باشد (و بالاترین اطمینان را داشته باشد)، به عنوان جواب نهایی انتخاب شده و محاسبه می‌شود.
// نمونه‌ای از تولید واریانت‌های تصویری در MathOcrSolver.ts
const createBase = () => sharp(png).flatten({ background: "#ffffff" }).grayscale();
return Promise.all([
    finish(createBase().normalise()),
    finish(createBase().normalise().threshold(128)),
    finish(createBase().normalise().threshold(160)),
    finish(createBase().normalise().threshold(190)),
    finish(createBase().normalise().threshold(210)),
]);

۵-۲. مدیریت کش کپچا (Captcha Caching)

برای صرفه‌جویی در زمان و منابع پردازشی (Tesseract سنگین است)، ماژول captchaCache.ts طراحی شده است. این ماژول تصویر کپچای فعلی را با تصاویر قبلی که با موفقیت حل شده‌اند (ذخیره شده در پوشه captcha/) مقایسه می‌کند. مقایسه با استفاده از همبستگی متقابل نرمال‌شده (NCC) پیکسل به پیکسل انجام می‌شود. اگر میزان شباهت بالای ۹۳٪ باشد، جواب از کش خوانده می‌شود و OCR اجرا نمی‌شود.

فصل ششم: چالش‌های مهندسی و راه‌حل‌ها

۶-۱. چالش CORS و MIME Type در Playwright

در حین توسعه، مشاهده شد که سایت USPTO به دلیل تنظیمات امنیتی (CSP و CORS)، اجازه لود شدن اسکریپت‌های داخلی خود را در محیط اتوماسیون نمی‌دهد و خطای Failed to fetch dynamically imported module می‌دهد.

راه‌حل: در فایل index.ts، تنظیمات مرورگر به شکل زیر تغییر کرد:

const context = await chromium.launchPersistentContext(config.browserProfileDir, {
    // ...
    bypassCSP: true, // نادیده گرفتن Content Security Policy
    args: [
        '--disable-web-security', // غیرفعال کردن امنیت CORS
        '--disable-features=IsolateOrigins,site-per-process',
        '--disable-blink-features=AutomationControlled', // مخفی کردن ربات بودن
        '--no-sandbox',
    ],
    ignoreDefaultArgs: ['--enable-automation'],
});

۶-۲. مشکل Timeout در حالت networkidle

سایت USPTO یک اپلیکیشن Angular است که مدام در پس‌زمینه با سرور در ارتباط است (WebSocket, Polling). به همین دلیل، هرگز حالت networkidle رخ نمی‌دهد و دستور page.goto() با خطای Timeout کرش می‌کند.

راه‌حل: تمام دستورات waitForLoadState("networkidle") در کل پروژه (مخصوصاً در JobOrchestrator و AuthService) به waitForLoadState("domcontentloaded") تغییر یافتند تا به محض آماده شدن ساختار HTML، عملیات بعدی انجام شود.

۶-۳. چالش اجرای فرآیندها در ویندوز (EINVAL)

از نسخه Node.js 18.20 به بعد، به دلیل یک آسیب‌پذیری امنیتی، اجرای فایل‌های .cmd (مثل pnpm) با خطای spawn EINVAL مواجه می‌شود. برای حل این مشکل در فایل runner.ts، دستور اجرای برنامه به صورت یک رشته واحد (Single String) درآمده و گزینه shell: true به آن اضافه شد تا توسط cmd.exe ویندوز اجرا شود.

فصل هفتم: استقرار و راه‌اندازی

۷-۱. استقرار در محیط ویندوز

در ویندوز، نیاز به نصب Node.js، pnpm و MySQL (مثلاً از طریق XAMPP) است. مسیر مرورگر Chrome باید در فایل .env تنظیم شود. سپس با دستور pnpm run runner برنامه اجرا می‌شود.

۷-۲. استقرار در محیط لینوکس (Ubuntu Server)

در سرورهای لینوکس بدون رابط گرافیکی (Headless)، نیازی به نصب مرورگر Chrome نیست. Playwright خودش Chromium را نصب می‌کند. برای اجرای همیشگی در پس‌زمینه، از ابزار PM2 استفاده می‌شود:

# نصب PM2
sudo npm install -g pm2

# اجرای برنامه در پس‌زمینه
pm2 start pnpm --name "uspto-bot" -- run runner

# ذخیره تنظیمات برای اجرای خودکار پس از ری‌استارت سرور
pm2 save
pm2 startup
